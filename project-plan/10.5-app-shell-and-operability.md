# Milestone 10.5 — App Shell, Navigation, Operability & Review Remediation

> **Slots between:** M10 (merged `d574057`, PR #29 — operator track live-verified 2026-07-11) and M11 (Hardening — not started).
> **Duration:** planning label only, not a constraint.
> **Depends on:** M10 merged.
> **Unlocks:** M11 (you cannot load-test or beta a product that cannot be navigated), M12 (beta sign-off).
> **Branch:** `feature/m10.5-app-shell-and-operability`.

> **Why this milestone exists.** Every feature milestone M03–M10 shipped its *screens* and almost none of them wired those screens to anything a user can click. `frontend/src/app/app.component.ts:9` is a bare `template: \`<router-outlet />\``; the root route renders an M00 scaffold (`features/landing/landing.component.ts`) with **zero links**; and there is **no logout anywhere in the codebase** (`grep -rn "logout" frontend/src/app/features/` → 0 hits). 8 of the app's authenticated routes are reachable only by typing a URL — including `/settings/brokers`, the one screen the product exists to enable. This was live-verified on 2026-07-12: `http://localhost:4444/` is a dead end, `/dashboard` correctly bounces an anonymous user to `/login`, and `/login` has no link back to the front door. In parallel, a full `/engineering:code-review` and `/design:design-critique` (both 2026-07-12, evidence in §18) surfaced 3 backend security defects and a family of frontend correctness + accessibility bugs that CI cannot see. This milestone makes the app **operable, honest, and safe to hand to a beta user.**

> **REVIEWED & FROZEN 2026-07-12** — every code reference below was verified against `main` at the time of writing (see §18 "Evidence ledger"). Ten decisions are settled; do **not** revisit them autonomously:
>
> 1. **A single `ShellComponent` wraps all authenticated routes** via a component-ful parent route with `canMatch: [authGuard]`; auth pages (`/login`, `/register`, …) and the public landing stay OUTSIDE the shell. The exact route tree is frozen in §7.1.
> 2. **Logged-out `/` = a real landing page** (what the product does + how the webhook→risk→broker flow works + Sign in / Create account CTAs). **Logged-in `/` redirects to `/dashboard`** via a `landingGuard` (reuses `guestGuard` semantics). No forced product tour.
> 3. **In-app onboarding = a state-driven "Getting started" checklist**, not a modal tour. It reads real backend state and renders as the dashboard empty state + a persistent nav item until complete; it never fabricates progress. The steps are exactly the four booleans returned by `GET /api/v1/onboarding/status/` (§9): **(0) MFA enrolled → (1) broker connected → (2) strategy enabled *with its webhook secret configured* → (3) first paper fill seen.** MFA is step 0 (not a separate "webhook" step) because the live pass proved the app 403s on every data endpoint until MFA is enrolled; "configure your webhook" is folded into the strategy step, not a standalone signal. AC-10.5-5, §7.3, and §9 all use this same four-step definition.
> 4. **Navigation copy uses the `nav.*` i18n keys that already exist** in `frontend/src/assets/i18n/en.json` (`dashboard, strategies, backtest, risk, admin, settings, login, logout`) — they were translated for a navbar that was never built. No new hardcoded English in the shell.
> 5. **Six shared presentational components** get extracted (`Button`, `Card`, `Modal`, `EmptyState`, `Spinner`, `PageHeader`) + **one global `ToastService`**. Feature screens are migrated onto them where they touch this milestone's other work; a full sweep of all ~25 screens is explicitly a fast-follow, not a blocker (§3).
> 6. **Security fixes C1/C2/C3 ship in this milestone and are release-blocking** (§7.6). They are independent of the shell work and may land first. C2 (missing-env fail-closed) and C1 (broken auth rate-limit key) are one deploy away from real harm.
> 7. **The risk engine is made truthful** (§7.7): the soft-stop dead code (AC-08-12) is either wired to a real intraday-drawdown input or removed; the three unenforced `RiskProfile` fields are either enforced or removed from the model+UI; and `compute_size` stops silently discarding the alert's `requested_qty`. No half-enforced control ships with a UI that claims it works.
> 8. **`PROGRESS.md` gets an honest INERT ledger** (§7.9). Code that is merged + CI-green but structurally incapable of producing output in any deployed config (regime plane, sentiment scoring, TradeStation, backtest worker, soft-stop, Alpaca missed-fill recovery) is recorded as INERT with the reason and the milestone that owns the real fix. This milestone does **not** try to make regime/sentiment produce real data (that needs external API keys — operator/M11) or build the Railway backtest worker (that is M11 §7.0 `SERVICE_ROLE`); it records the truth and fixes only what is fixable in-repo without externals.
> 9. **The M02 session-revoke bug is fixed here** (§7.6, SEC-4). "Revoke other sessions" and password-change currently log the user out of their *own* session because `_current_family_jti()` returns the `family_id` claim and matches it against the `current_jti` column (`views_m02.py:82,419-424`). It is a real, shipped auth-correctness bug and belongs with the security track.
> 10. **Accessibility work targets WCAG 2.1 AA on the screens this milestone touches** (shell, landing, login, security, admin-MFA, the two modals, dashboard). A full-app a11y audit is M11 §7.10; this milestone fixes the labeling/focus-trap/keyboard defects on the surfaces it is already editing.

## 1. Purpose

Turn a set of disconnected, individually-built screens into a coherent, navigable, self-explanatory application, and close the security + correctness defects that a green CI has been hiding. After M10.5:

- A first-time visitor understands what StratTraderPro is and can reach sign-in by clicking.
- A signed-in user can navigate to every feature, knows what to do first, and can sign out.
- Every authenticated screen sits inside one shell with consistent chrome, error surfacing, and the impersonation banner.
- The three backend security defects and the M02 session bug are fixed and regression-tested.
- The risk engine no longer advertises controls it does not enforce.
- `PROGRESS.md` tells the truth about what actually runs.

## 2. In Scope

- **App shell** (`ShellComponent`): responsive header, primary nav (role-aware), user menu with **logout**, impersonation-banner slot, `<router-outlet>` for children.
- **Route restructure** (`app.routes.ts`): public landing + auth routes outside the shell; all authenticated features as children of the shell route; `/` redirects authed users to `/dashboard`; a real 404 page replacing the silent `** → ''` redirect.
- **Landing page** rewrite: product explanation, the webhook→risk→broker flow, Sign in / Create account CTAs, honest environment badge driven by runtime config (not the hardcoded "Platform scaffold — staging environment" string).
- **Onboarding**: state-driven "Getting started" checklist component + dashboard empty state; wire the 13 orphaned `frontend/src/assets/help/*.html` articles to a `/help/:slug` viewer and add help affordances next to jargon.
- **Shared UI kit**: `Button, Card, Modal (focus-trapped), EmptyState, Spinner, PageHeader` + global `ToastService`/`<app-toast-host>`.
- **Frontend correctness**: fix the refresh interceptor auth-endpoint handling (C-FE-1), the missing `auth.login.error.UNKNOWN` + `MissingTranslationHandler` (C-FE-2), the error-interceptor prototype-spread (C-FE-3), the shared-WebSocket lifecycle/logout teardown (C-FE-4), and the ~10 swallowed-error sites (H-FE block).
- **Backend security**: C1 (auth rate-limit key), C2 (fail-closed on missing `SECRET_KEY`/`FERNET_KEK`), C3 (throttle MFA step-up), SEC-4 (M02 session revoke), plus `/admin/` login hardening (H8) and the `/metrics` fail-closed (M1).
- **Risk truthfulness**: AC-08-12 soft-stop, unenforced `RiskProfile` fields, `requested_qty` clamp, AC-08-6 ×0.5-vs-×0.70 ruling.
- **Accessibility** on touched screens: input labels (security + admin-MFA), modal focus traps + Escape, keyboard-reachable table rows, text alternatives for the regime band + backtest canvas.
- **Status-doc correction**: honest INERT ledger in `PROGRESS.md`; delete the three empty `" 2"` directories.

## 4. Frozen decisions

See the ten frozen decisions in the header block. Additionally:

- **F-11. Shell state source:** the shell reads the current user from the existing `AuthStore` (`store.user()`, already exposes `is_staff`) — no new store. Onboarding state comes from a new lightweight `GET /api/v1/onboarding/status/` (§9), computed server-side from existing models, so the client never guesses.
- **F-12. No new frontend deps.** Focus-trap, toasts, and the modal are built on Angular CDK **only if `@angular/cdk` is already a dependency**; otherwise they are implemented in-house (≤40 lines each). - **F-13. Landing content is honest.** It describes what the platform *does* (paper trading via Alpaca, TradingView webhooks, regime/sentiment-aware sizing, kill switches) without claiming live-trading or real-money readiness, which are not shipped.

## 5. Acceptance Criteria

Operability & shell:

- **AC-10.5-1** From `http://<app>/` a logged-out user can reach the login page **by clicking** (no URL typing). The landing page names the product and explains, in one screen, the webhook→risk→broker flow, with visible "Sign in" and "Create account" CTAs.
- **AC-10.5-2** A logged-in user sees a persistent shell (header + nav + user menu) on every authenticated route. The nav links reach `/dashboard`, `/strategies`, `/backtest`, `/risk`, `/orders`, `/settings/*`, and (staff only) `/admin` — each verified reachable by click from `/dashboard`.
- **AC-10.5-3** A logged-in user can **sign out** from the user menu; logout clears auth state, tears down the dashboard WebSocket, and lands on `/` (or `/login`).
- **AC-10.5-4** Visiting `/` while authenticated redirects to `/dashboard`. Visiting an unknown path **while authenticated** renders a real **404 page** with a link home — not a silent redirect to the landing scaffold. **While anonymous**, an unknown path redirects to `/login?next=<path>` (the shell's `canMatch:[authGuard]` intercepts before the `**` route is reached — this is expected and acceptable; a random URL from a logged-out visitor sensibly lands on sign-in). Both behaviors replace today's silent `** → ''` redirect to the scaffold (live-verified broken 2026-07-12).
- **AC-10.5-5** A brand-new user lands on a dashboard whose empty state is a **"Getting started" checklist** of the four steps defined in frozen decision 3 and §9: **Enable two-factor authentication → Connect a broker → Add/enable a strategy (with its webhook configured) → See your first paper fill.** Each step deep-links to the right screen (MFA → `/settings/security/mfa/setup`, broker → `/settings/brokers`, strategy → `/strategies`, fill → `/dashboard`) and reflects **real** completion state from `GET /api/v1/onboarding/status/`. MFA is step 0 because, until it is enrolled, every dashboard data endpoint returns 403 (live-verified 2026-07-12).
- **AC-10.5-6** Every jargon term with a matching article in `assets/help/` (PBO, MAR, regime, kill switch, tearsheet, TradingView alert config, Alpaca connect, …) has a help affordance that opens the article at `/help/:slug`. No help article is orphaned; no `/help/:slug` 404s for a slug that has a file.

Security & correctness (release-blocking):

- **AC-10.5-7** With `RATELIMIT_ENABLE=True`, two different submitted emails hit **two different** login-rate-limit buckets (C1 fixed). A regression test asserts this; the login endpoint is no longer a 5-requests-to-DoS-everyone surface.
- **AC-10.5-8** In prod settings, an unset `SECRET_KEY` or `FERNET_KEK` **fails the boot** (raises), and a boot-time assertion rejects the known insecure default (C2). Test via a prod-settings import with the env unset.
- **AC-10.5-9** The MFA step-up path (`verify_mfa_code` callers in `risk/views.py`, `brokers/views.py`, `admin_portal/views.py`) is rate-limited: N failures per user per window → lockout + audit event (C3).
- **AC-10.5-10** "Revoke other sessions" and password-change revoke **every family except the caller's own**, and the caller's session keeps working (SEC-4 / M02 AC-02-8/10 fixed). A test authenticates as a specific family and asserts that family survives.
- **AC-10.5-11** A failed login (wrong password) does **not** trigger `facade.logout()`/refresh, is **not** submitted twice, and renders a human-readable message (never the raw string `auth.login.error.UNKNOWN`) (C-FE-1 + C-FE-2).
- **AC-10.5-12** The risk engine advertises no control it does not enforce (§7.7): the soft-stop either fires on real intraday drawdown or is removed; `max_concurrent`/`leverage_cap`/`permitted_asset_classes` are enforced or removed from model+serializer+UI; and an alert's `requested_qty` is respected (clamped, not silently discarded). Each resolved field has a test.

Accessibility & consistency:

- **AC-10.5-13** On every screen this milestone touches, all form inputs have programmatic labels; the two modals (`webhook-config`, `halt-platform`) and the orders drawer trap focus, restore focus on close, and close on Escape; clickable table rows in `/orders` and `/backtest` are keyboard-operable; the regime band and backtest canvas expose a text alternative. Verified with a manual keyboard pass + the axe checks added in §11.
- **AC-10.5-14** The shell, landing, and the six shared components use the design tokens (`--color-primary-*` etc.) via Tailwind classes; no new `bg-blue-600` literals are introduced in code added by this milestone. Error toasts replace at least the swallowed-error sites listed in §7.5.

  // Public landing — redirect authed users to /dashboard (landingGuard).
  { path: '', pathMatch: 'full', canMatch: [landingGuard],

Implementation notes (frozen):

- The existing `*.routes.ts` arrays (`SETTINGS_ROUTES`, `STRATEGIES_ROUTES`, `RISK_ROUTES`, `BACKTEST_ROUTES`, `ADMIN_ROUTES`) are today mounted via wrapper entries in `app.routes.ts` that use `path: ''` + `loadChildren`; the child routes themselves carry their **full within-shell paths** (`settings/profile`, `strategies/:id`, `backtest/:id`, `admin/users`, …) and each carries its own `canMatch:[authGuard]` (admin additionally `adminGuard`). **Convert each array to a plain exported list of those same child routes** (drop the redundant per-route `authGuard` — the shell parent enforces it once) and spread them under the shell `children`, keeping the paths identical. **Keep `adminGuard`** on the admin child routes (staff gate is separate from the auth gate). Verify each converted file still `ngc`-compiles and `ng build`s.

Confirm with a manual test: anonymous `/orders` → `/login?next=/orders`.

**404 component** `features/shared/not-found/not-found.component.ts`: `<h1>`, a short "page not found" message (i18n key `errors.not_found.*`), and a link to `/` (or `/dashboard` if authed). ### 7.5 Frontend correctness → AC-10.5-11 and swallowed-error cleanup

**C-FE-1 — refresh interceptor must not run on auth endpoints.** `core/interceptors/refresh.interceptor.ts:19` excludes only `/auth/refresh/` and `/auth/logout/`. A `401` from `/auth/login/` (wrong password) therefore enters the refresh path: with no refresh token yet it hits `line 28 → facade.logout()` (which clears state and navigates), wiping the error the user needs to see; if a stale refresh token exists it will `retryWithNewToken` and **re-submit the login POST**, double-counting the backend lockout/rate-limit. **Fix:** broaden the skip list to all auth endpoints — `/auth/login/`, `/auth/register/`, `/auth/mfa/verify/` (confirm the exact verify path in `apps/users/urls.py`), `/auth/password-reset`, `/auth/oauth/`. Add an integration test: a `401` on `/auth/login/` does not call `refreshSession()` or `logout()` and the error propagates.

**C-FE-2 — missing translation renders the raw key.** `app.config.ts` `TranslateModule.forRoot({ defaultLanguage: 'en', loader })` has **no `missingTranslationHandler`** and no `useDefaultLang`. `auth.facade.ts:246` can set `code: 'UNKNOWN'`, and `en.json` `auth.login.error` has only `INVALID_CREDENTIALS, ACCOUNT_LOCKED, EMAIL_NOT_VERIFIED, RATE_LIMITED` (verified 2026-07-12) — so the login page can literally show `auth.login.error.UNKNOWN`. **Fix (three parts):** (a) add `auth.login.error.UNKNOWN` to `en.json`; (b) register a `MissingTranslationHandler` in `forRoot` that returns a sensible fallback (e.g. the params' `default` or a generic message) instead of the key; (c) delete the dead `{ default: err.message }` interpolation arg in `login.component.ts:19` (ngx-translate's 2nd pipe arg is interpolation params, not a fallback — the strings have no `{{default}}`). Verify the backend's `ApiError.code` casing (`apps/users/serializers.py` / the error envelope) matches the uppercase keys in `en.json`; if the backend emits lowercase, every login error would miss — fix by normalizing on one side and add a test.

**C-FE-3 — error interceptor destroys the error prototype.** `core/interceptors/error.interceptor.ts:20` does `return throwError(() => ({ ...err, appError }))`, spreading `HttpErrorResponse` into a plain object so `err instanceof HttpErrorResponse` is false downstream. Compounding it, two unwrap conventions coexist: `auth.facade.ts:246` reads `e.error.error`; the dashboard/other facades read `e.appError.apiError`. **Fix:** attach `appError` without breaking the prototype (`(err as any).appError = appError; return throwError(() => err)` or a typed wrapper class), and standardize all facades on the `appError` envelope. Grep every `?.error?.error` and `.appError` in `abstraction/facades/` and converge them; add/adjust facade specs.

**C-FE-4 — shared WebSocket never torn down on logout.** `core/services/ws.service.ts` is a `providedIn:'root'` singleton shared by the dashboard and backtest facades; `BacktestFacade.stop()` deliberately leaves it open, and nothing calls `ws.disconnect()` on logout — so a 25s-heartbeat, auto-reconnecting socket can outlive the session. **Fix:** call `ws.disconnect()` from `AuthFacade.signOut()` (§7.1), and reference-count connect/disconnect so the last detaching subscriber closes it. Also address the module-level `isRefreshing`/`refreshDone$` deadlock risk noted in review C4 by adding a timeout+reset around the refresh promise (low-risk, same file as C-FE-1). *(Live note 2026-07-12: the dashboard WS showed "Offline" for the logged-in user — confirm whether that is the token-in-query-string auth (H-FE below) failing or an expected dev state while verifying this fix.)*

### 7.6 Backend security (release-blocking) → AC-10.5-7, -8, -9, -10

**C1 — auth rate-limit key is broken in prod.** `apps/users/views.py:52` `_email_keyer` reads `request.data` (a DRF attribute) on the raw Django request django-ratelimit passes, raising and collapsing every email-keyed limit to the literal `"anon"` — one global bucket for login (`:357`), register (`:151`), password-reset (`:474`), resend (`:237`). The identical bug was already fixed for MFA verify by switching to `key="ip"` (`views_m02.py:245-255`). **Fix:** make `_email_keyer` raw-request-safe — parse the email from `json.loads(request.body or b'{}')` inside a `try/except` — **or** drop the email keyer and rely on `key="ip"` + the existing `FailedLoginAttempt` per-account lockout (`services.py:217`). Prefer the parse-body approach so the per-account limit survives. **Test:** with `RATELIMIT_ENABLE=True` (override the `test.py:38` default in this test only), two different emails get two independent buckets; a third request for one email is limited while the other is not.

**C2 — prod boots on a public default secret.** `config/settings/base.py:23` `SECRET_KEY = env("SECRET_KEY", default="insecure-dev-key-change-in-prod")`, and `prod.py` never re-reads it without a default; `JWT_SIGNING_KEY` (`:249`) and `FERNET_KEK` (`:282`) both derive from it. A missing env var silently ships a forgeable JWT key and a derivable KEK for every stored broker secret/TOTP. **Fix:** in `config/settings/prod.py`, `SECRET_KEY = env("SECRET_KEY")` and `FERNET_KEK = env("FERNET_KEK")` with **no default** (django-environ raises when unset), plus `assert SECRET_KEY != "insecure-dev-key-change-in-prod"` and an assert that `FERNET_KEK` is not the SHA-derived dev default. Fail the boot. Note the JWT signing key is transitively covered: `SIMPLE_JWT["SIGNING_KEY"]` defaults to `SECRET_KEY` (`base.py:249`), so once `SECRET_KEY` is guaranteed non-default the JWT key is safe when `JWT_SIGNING_KEY` is unset — optionally add a parallel assert on `SIMPLE_JWT["SIGNING_KEY"]` for defense in depth. **Test:** importing `config.settings.prod` with those env vars unset raises (respect the existing prod-import smoke pattern; guard so it doesn't break the normal smoke that sets them).

**C3 — MFA step-up is unthrottled.** `verify_mfa_code(user, code)` (`apps/users/mfa.py:207`) is the single chokepoint for all three step-up callers (`risk/views.py:139`, `brokers/views.py:159`, `admin_portal/views.py:69`) and has no rate limit — a stolen access token can brute-force a fresh TOTP (valid_window=1 ⇒ 3/10⁶ live) to release a kill switch, remove a broker, or take an admin action. **Fix:** add a per-user failure counter inside `verify_mfa_code` (Redis `cache`): on each failure `cache.incr` a `mfa_stepup_fail:{user_id}` key (set TTL on first miss); at ≥ N (e.g. 5) within the window (e.g. 15 min) return `False` without checking and emit an audit event (`apps/audit`), reset the counter on success. This is safe because `verify_mfa_code` is used **only** by step-up (login MFA uses a different, already-IP-limited path — verified: grep shows only those three callers). **Test:** 5 bad codes → the 6th is rejected pre-check and an audit row is written; a good code before the cap still works and resets.

**SEC-4 — M02 "revoke other sessions" logs you out of your own session (AC-02-8/10 broken).** `apps/users/views_m02.py:82` `_current_family_jti()` returns the token's **`family_id`** claim, but callers (`:419-424`, `:469-476`) look it up as `RefreshTokenFamily.objects.filter(current_jti=<that value>)` — a `family_id` never equals a `current_jti`, so `current_family_id` stays `None`, `revoke_other_sessions(except_family_id=None)` (`services.py:428-432`) excludes nothing, and the caller's own family is revoked. **Fix:** rename/repurpose the helper to return the **family_id** and pass it straight to `except_family_id` (drop the incorrect `current_jti` lookup) — the access token already carries `family_id` (`services.py:104,411`). Fix the sessions-list "current" flag the same way (`services.py:416`). **Test:** authenticate as family A, call revoke-all-other with families A/B/C present → B and C revoked, **A survives**; password-change likewise keeps the current family. Tighten the existing `test_mfa.py` assertions that only checked `revoked >= N`.

**H8 — Django `/admin/` is an unthrottled staff-password surface.** `config/urls.py:63` mounts stock `admin.site.urls` with session auth, no MFA, no lockout, and `UserAdmin` exposes `is_staff`/`is_superuser` as editable — bypassing the M10 `IsAdminAndMFAEnforced` design. **Fix (minimal, this milestone):** in prod, gate `/admin/` behind an MFA-enforcing `AdminSite` subclass **or** unmount it (`if not settings.DEBUG`) and rely on the `/api/v1/admin/` portal. If a fuller hardening is preferred, cross-reference it into M11 §7.1 and do the unmount now as the safe default. **Test:** prod urlconf does not expose `/admin/login/` (or it enforces MFA).

**M1 — `/metrics` fails open in prod.** `config/metrics_endpoint.py:47` returns `True` (auth ok) when no basic-auth creds are set, and `prod.py:52-56` only **warns**. **Fix:** in prod, refuse to serve `/metrics` (401) — or refuse to boot — when `METRICS_BASIC_AUTH_USERNAME/PASSWORD` are unset and `DEBUG is False`. **Test:** prod-config path returns 401 without creds.

### 7.7 Risk-engine truthfulness → AC-10.5-12
