## 1. Purpose

Lay the invariant foundation on which all subsequent milestones are built: repository, CI, cloud environments, baseline Django/Angular apps, observability skeleton, and developer tooling. Nothing user-facing ships here; the deliverable is a runnable "hello world" end-to-end deployable to staging.

## 2. In Scope

- GitHub repository with branch protection, issue + PR templates, Dependabot.
- Monorepo layout per master plan §4.
- Django 5 + DRF scaffold per `django-angular-project-setup` skill.
- Angular 19 standalone + signals scaffold per `frontend` skill, with 3-layer `core / abstraction / presentation` directory shell.
- Dockerfiles (backend, frontend) + `docker-compose.yml` for local dev (postgres, redis, backend, frontend, ngrok).
- Railway project with 6 services (backend, worker, beat, llm-worker, frontend, postgres+redis plugins) in **staging** env.
- CI pipeline (lint + test + build + trivy + deploy-staging).
- Sentry, Prometheus, OTel SDK installed and configured (producing data even if empty).
- `/healthz` and `/readyz` endpoints returning 200.
- Angular landing page reachable on staging HTTPS URL.
- `CHANGELOG.md`, `CONTRIBUTING.md`, ADR directory structure.
- i18n scaffolding (`ngx-translate` + Django `locale/`) wired, even though only `en.json` exists.

## 3. Out of Scope

- Any auth, user model beyond Django's stub.
- Any business logic (no strategies, no broker, no sentiment).
- Production Railway environment (staging only).
- Custom domains (use Railway default subdomains in M00).

## 7. Tech Stack Notes

- **Python 3.12** chosen for performance and maturing async story.
- **Django 5.x**: stable LTS-adjacent; async views available though not required in this milestone.
- **Angular 19**: standalone components + signals is the mainline style; zone-less where possible.
- **pnpm** over npm for workspace performance.
- **drf-spectacular** over DRF's default schema because it produces valid OpenAPI 3.1 usable with `openapi-typescript`.
- **Railway** chosen per §2 of master plan; no lock-in — Dockerfiles are portable to Fly/Render/k8s.

## 13. Translation & Localization

This is where the i18n skeleton lives. Every future milestone assumes:

- **Angular:** add keys to `src/assets/i18n/en.json`; never hard-code user-facing strings.
- **Django:** wrap strings with `_()` (`from django.utils.translation import gettext_lazy as _`).
- **Email templates:** wrap in `{% blocktrans %}` and store in `templates/email/*.html`.
- **Date / time:** always UTC in storage, rendered via `date` pipe with user's IANA tz.
- **Currency / number:** never use `toFixed()`; use `Intl.NumberFormat`.
- **Extract commands documented** in `README.md`:
  - `python manage.py makemessages -l en -a`
  - `ng extract-i18n` is not used (we use ngx-translate JSON, not XLIFF) — document the convention.

At M00 we only ship `en`. Layout uses logical properties so RTL locales (Hebrew, Arabic) can be added later without refactors.
