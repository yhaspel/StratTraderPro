Why Market Regime says "no data"

The Market Regime card on the dashboard classifies the market as BULL, CHOP, BEAR or CRISIS from a daily feature vector. On a working deployment it looks like this:

If yours is empty, this guide explains why and what to do. It is a self-hosting / operator topic — if you did not deploy this instance yourself, send it to whoever did.

Where the data comes from

Nothing about the regime is computed in the browser. A nightly Celery task, apps.regime.tasks.compute_features_daily, fetches the day's inputs, standardizes them into a feature vector, stores a snapshot, and writes one RegimeObservation. The card renders the most recent observation; the band renders the last ~90.

The inputs come from two external providers:

ProviderSettingSupplies
Financial Modeling PrepFMP_API_KEYDaily equity bars (SPY and sector proxies)
FRED (St. Louis Fed)FRED_API_KEYVIX, high-yield and investment-grade credit spreads, 2y/10y yields, dollar index

The actual failure mode

If either key is missing, the daily task returns immediately with {"skipped": "no_market_data_source_configured"}. It does not error, it does not retry, and it does not write a partial observation — it is a deliberate no-op, so that the history is not polluted with fabricated neutral values that would bias the model for months once real keys arrive.

The visible consequence is that the table of observations stays empty forever, the HMM never has enough rows to train, and the card has nothing to show. From the dashboard alone that is indistinguishable from a broken pipeline, which is why the card now names the cause instead of just saying "no data yet".

Checking, without reading logs

Staff accounts can see the answer directly at Admin → Health → Regime data source. It reports Configured or Not configured from the same function the task uses, so it cannot drift from reality.

Two nearby cards are worth reading at the same time:

  • HMM model age — — means no model has ever been activated, which is expected while there is no feature history.
  • Sentiment backlog — unrelated pipeline. Sentiment can be perfectly healthy while regime is empty; they use different providers.

Fixing it

  1. Get an API key from each provider. FRED keys are free; FMP has a free tier that covers the daily bars this uses.
  2. Set FMP_API_KEY and FRED_API_KEY on every service that runs Django code — the web service, the Celery worker and Celery beat. Setting them on the web service alone is the most common mistake: the task runs on the worker, so the web tier reporting "configured" while the worker is not means nothing ever gets written.
  3. Redeploy so the processes pick up the new environment.
  4. Re-check Admin → Health. It should now read Configured.

What to expect afterwards

The pipeline is daily, not on-demand. After the keys are set:

  • The first observation appears after the next scheduled run (22:30 UTC), so the card can stay empty for up to a day. That is normal.
  • The card will show the rule-based classification straight away and mark itself degraded until an HMM model is trained.
  • Training needs roughly 120 daily snapshots before the nightly retrain will fit a model, so expect months of accumulation — or backfill the history from the providers — before the card stops reporting degraded.
  • The history band fills in one segment per day as observations accumulate.
Degraded is not broken. A degraded regime is rule-based only: it still classifies, it just does not have the trained model's state probabilities behind it. Treat the label as directional, not precise.
