Running your first backtest

A walk-forward backtest tests a strategy the honest way: it tunes the strategy's parameters on a stretch of history (the train window), then measures how those tuned parameters actually performed on the following stretch it never saw (the test, or out-of-sample, window). It rolls that train-then-test window forward across your whole date range and stitches the out-of-sample pieces into one continuous equity curve. Good in-sample results are easy; stable out-of-sample results are what earn a strategy the right to trade.

Open Backtest (/backtest) and click New backtest.

1. Pick a strategy

Only strategies with a registered backtest adapter can be run. The picker enables those and greys out the rest with a "Backtest not available — no Python adapter registered" banner.

Why can't I backtest my uploaded strategy? Backtesting runs the strategy's logic on our servers, and for safety we never execute uploaded Pine or community code. A strategy is backtestable only when it has an in-repo Python adapter written for it. The built-in SMA Cross Demo (sma-cross-demo) ships with one, so it's the easiest way to see a full run end to end.

2. Choose symbols and a date range

  • Symbols — 1 to 10. Each symbol is walk-forwarded independently and gets its own out-of-sample curve and metrics; there's no cross-symbol portfolio allocation.
  • Date range — up to 15 years, daily bars only in this release. The data comes from your local market-data store, so a symbol needs to be backfilled first. If coverage is thin you'll get BACKTEST_INSUFFICIENT_DATA naming the biggest gaps — backfill the symbol and retry.

3. Set the train / test windows

Three numbers, in calendar days:

FieldWhat it does
Train windowHow much history each window uses to pick the best parameters.
Test windowHow much out-of-sample history each window is then measured on.
StepHow far the window slides each time. In this release it is locked equal to the test window, so the out-of-sample pieces line up end-to-end with no gaps or overlaps.

Mode controls the train window: Rolling slides a fixed-length train window forward; Anchored keeps the start pinned and grows the train window each step. Your range must fit at least 2 complete windows — for example, a 1-year range with a 180-day train and 60-day test gives 3 windows.

Too few windows? If the range can't fit two full train+test windows the run is rejected. Widen the date range, or shrink the train/test windows.

4. Metric, cash, and costs

  • Ranking metric — how each window picks its "best" parameters from the sweep: sharpe (default), sortino, total_return, or mar.
  • Initial cash — starting equity per segment (default 100,000). Each out-of-sample segment replays from this same amount; the pieces are compounded afterward into the full curve.
  • Costs — slippage in basis points (default 5, floor 1), optional per-order and per-share commission (default $0, Alpaca-style), and the volume-participation cap for partial fills (default 10% of a bar's volume). The costs you choose are printed on the tearsheet cover.

5. Choose a sizing mode

This decides how many shares each entry buys:

ModeWhat it does
Fixed qty 1 Every entry buys exactly 1 share. Simplest way to see the raw shape of a strategy's signals, independent of position sizing.
Production sizing
(regime/sentiment neutralized)		 Sizes each entry with the same risk engine that sizes your live orders — your risk profile's per-trade risk, ATR-based stop, position cap, and lot rounding — so the backtest reflects how big your real positions would have been.
What "regime/sentiment neutralized" means. Live sizing also reacts to the current market regime and news sentiment. A historical backtest has no live regime or sentiment feed, so those inputs are held neutral (regime = NEUTRAL, sentiment = 0). Everything else — your risk percentage, ATR stop, position cap — is applied exactly as in production.
No risk profile yet? Live trading skips sizing entirely until you create a risk profile (your alert qty is used as-is). A backtest is different: in Production sizing mode it uses your profile's default values so it can still produce a sized curve. If you haven't tuned a risk profile, treat a Production-sizing backtest as "sized with the defaults," not "sized like my configured account."

6. Advanced: parameter grid and retention

  • Parameter grid — a JSON object of { "name": [values] } that narrows the strategy's built-in parameter space (e.g. { "fast": [5, 10], "slow": [20, 30] }). It must be a subset of what the strategy declares; leave it blank to sweep the full grid. The editor validates the JSON as you type. Total combinations are capped at 500.
  • Retention — how long the downloadable report is kept (default 90 days, up to 365). After that the metrics stay but the report files are evicted.

7. Submit and watch it run

Submit, and you land on the run detail page. A live progress bar shows the stage — queued → loading → sweeping → replaying → reporting — with an ETA. You can leave and come back; the runs list shows status and lets you cancel an active run (it stops within about 30 seconds). When it finishes you get charts, a metrics table, per-window results, and JSON / HTML / PDF downloads. "Rerun with same config" clones everything back into the launcher.

Run sitting in "Queued" and not starting? The backtest worker may not be running in your environment. Backtests execute on a dedicated queue separate from order flow; if no backtest worker is provisioned, runs wait. This is an operator setup step — see the backtest-stuck runbook.
